# CN0582 WinUSB driver package

Installs WinUSB for the EVAL-CN0582-USBZ (`USB\VID_0456&PID_ED11`) on a new PC
**without running Zadig**, and in a way that works on **every USB port**.

```
cn-0582.inf         the driver package  (generated by Zadig/libwdi)
CN-0582.cat         its catalogue, self-signed by libwdi
cn0582_winusb.cer   the signing certificate, exported from the catalogue
install_driver.cmd  run as Administrator
```

## Install

Right-click `install_driver.cmd` -> Run as administrator. Or by hand:

```bat
certutil -addstore -f Root             cn0582_winusb.cer
certutil -addstore -f TrustedPublisher cn0582_winusb.cer
pnputil /add-driver cn-0582.inf /install
```

Then plug the board in, on any port.

## Why each step exists

**Why the certificate at all.** Windows will not silently install a driver
package whose catalogue it cannot verify. This catalogue is signed by a
certificate libwdi generated on the fly:

```
CN=USB\VID_0456&PID_ED11 (libwdi autogenerated)
thumbprint FAD08B30FC4369DA4499A2A427B7C970857178A4
expires    2029-01-01
```

**Why two certificate stores.** The certificate is self-signed, so it is its own
issuer. `Root` makes the chain validate at all; `TrustedPublisher` is what turns
an "is this publisher trusted?" prompt into a silent install. Zadig puts it in
both - one alone is not enough.

**Why it covers every port.** Windows binds drivers per *device instance*, and a
new port produces a new instance. But driver *selection* matches on the hardware
ID, and this INF claims `USB\VID_0456&PID_ED11` generically:

```ini
[Strings]
DeviceID = "VID_0456&PID_ED11"
```

Once the package is in the driver store it is a candidate for every instance, so
a new port is resolved automatically with no user action.

## The one thing that breaks it

Installing **CN0582 EVALUATION SOFTWARE** on the same machine. That adds ADI's
`hssi.inf`, which claims the same hardware ID (plus ten other ADI FX3 boards) and
binds the `adifx3` service instead of WinUSB. With both packages present, which
one wins on a newly-seen port is not predictable - that is exactly the port-to-port
inconsistency this package avoids.

If it has already been installed, remove it from an Administrator prompt:

```bat
pnputil /enum-drivers | findstr /i hssi
pnputil /delete-driver oemNNN.inf /uninstall /force
```

substituting the `oemNNN.inf` published name that the first command reports. Note
this also unbinds any other ADI FX3 hardware on that machine.

## Firmware

Program `MultiChannel_Vibration_Test.img` into the board's SPI flash and set
**S1-1 OFF, S1-2 ON** (SPI boot). The board then enumerates directly as
`0456:ED11` at power-on and never needs the vendor GUI. In USB-boot mode
(S1-1 ON, S1-2 ON) it comes up as the Cypress bootloader `04B4:00F3` instead and
waits for a firmware upload, which only the vendor software does.

## Verify

```bat
pnputil /enum-drivers | findstr /i cn-0582
```

and from the project venv:

```bat
.venv\Scripts\python.exe -c "import cn0582; d=cn0582.CN0582(); print(d.read_serial()); d.close()"
```

which should print the board serial, e.g. `ADI202302150064`.
